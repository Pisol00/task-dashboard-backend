## Project Overview

REST API backing the TaskFlow dashboard (DEVDEVA Fullstack take-home test).

Two features to support:
1. **Task board** — CRUD for tasks with search/filter/pagination + users for assignee selection.
2. **Daily Graph** — 24-hour metric points (3 series with different scales).

## Tech Stack

| Layer | Choice |
|---|---|
| Runtime | **Node.js 24** (LTS-class) |
| Framework | **Express 5** |
| Language | **TypeScript** (ESM, `verbatimModuleSyntax`, strict) |
| ORM | **Prisma 7** (PrismaClient + PrismaPg adapter) |
| Database | **PostgreSQL 16** (Docker for local dev) |
| Validation | **Zod** |
| Dev runner | **tsx** (watch mode) |
| Config | **dotenv** + Zod-validated `env.ts` |

### Prisma 7 notes

- Connection URL **does not** live in `schema.prisma` (Prisma 7 removed the `url` property).
- Config lives in `prisma.config.ts` at the project root and wires an adapter (`PrismaPg`) reading `DATABASE_URL` from `.env`.
- `PrismaClient` in `src/config/prisma.ts` also takes the adapter — keep it as the singleton.

### Important TS flags (tsconfig.json)

- `module: esnext`, `moduleResolution: bundler` — ESM-only
- `verbatimModuleSyntax: true` — `import type` required for type-only imports
- `noUnusedLocals` / `noUnusedParameters` — strict
- `paths: { "@/*": ["src/*"] }` — alias enabled

## API Contract (must match what FE expects)

Base path: `/api`

### Tasks

```
GET    /api/tasks?q=&priority=&status=&tag=&page=&limit=
  → { data: Task[], page, limit, total, totalPages }

GET    /api/tasks/:id        → Task
POST   /api/tasks            → Task (201)
PATCH  /api/tasks/:id        → Task
DELETE /api/tasks/:id        → 204
```

- `q` matches title case-insensitively
- `priority`, `status`, `tag` accept `"All"` to skip filtering
- All filters AND-combined
- **Pagination** is _per-status_: `limit` = max items per status, board returns up to `3 × limit` items (matches FE's TaskBoard layout). `totalPages` derived from busiest status.

### Users

```
GET /api/users → User[]
```

### Metrics

```
GET /api/metrics?date=YYYY-MM-DD → { date, points: MetricPoint[] }
```

- `date` defaults to today when omitted
- `points` always has 24 entries (hour 0-23) with `green` (0-100), `orange` (-100 to 100), `blue` (0-10)
- Missing rows are filled with `0` so the chart never breaks on empty days
- Seed covers 38 days: -30 / today / +7 (see `prisma/seed.ts`)

### Wire format

Backend stores enums as UPPER_SNAKE (`TODO`, `IN_PROGRESS`, `DONE`, `LOW/MEDIUM/HIGH`, `FEATURE/BUG/CHORE/DOCS`) but **API responses use the frontend's literal types** (`"To Do"`, `"In Progress"`, `"Done"`, etc.). Mapping happens in the service/mapper layer — never leak Prisma enums to the wire.

## Conventions

### Module pattern (per feature)

Every feature folder has `routes → controller → service → schema → mapper`:

- **routes**: Express Router. Mount middleware (`validate(...)`), call controller.
- **controller**: parse req, call service, send response. No business logic. Reads validated input via `getValidated(res, 'query'|'params'|'body')`.
- **service**: Prisma queries + domain logic. Pure (no Express types).
- **schema**: zod schemas for body/query/params.
- **mapper**: convert Prisma rows → wire types (and vice versa for inputs).

### Express 5 compatibility

`req.query` and `req.params` are **read-only getters** in Express 5, so we cannot mutate them after parsing. The `validate()` middleware therefore stashes parsed values on `res.locals.validated.{body,query,params}`, and controllers read them with the `getValidated()` helper.

### Rules

- **ESM imports** must use `.js` extension even for `.ts` files: `import { env } from './config/env.js'`
- **No `any`** — fail TypeScript if needed
- **Async errors** must be caught — use `try/catch` or wrap with `next(err)` in route handlers
- **Never expose Prisma enums** to API responses — always map through mapper
- **All input validation** through zod via `validate({ body, query, params })` middleware
- **Throw `ApiError`** (not raw Error) for HTTP errors
- **Use `prisma` singleton** from `@/config/prisma`

### Naming

- Modules: kebab-case folder, `<name>.<role>.ts` files
- Schemas: `taskCreateSchema`, `taskListQuerySchema`
- Services: verbs (`listTasks`, `createTask`, `updateTask`)

## Local Dev

```bash
# 1. Start DB
docker compose up -d

# 2. Generate Prisma client + run migrations
npm run db:migrate

# 3. Seed
npm run db:seed

# 4. Run server (watch mode)
npm run dev
```

Then API is at `http://localhost:3000/api/*`. Frontend dev server proxies `/api` → here.
